## 1. battery 模块详细设计

### 1.1 模块概述

电池电压采集模块，负责将 ADC 原始采样值换算为毫伏电压，并提供读取电池电压的高层接口。

**文件位置**：
- `app/battery/battery.h` —— 接口声明
- `app/battery/battery.c` —— 实现

### 1.2 硬件参数

| 参数 | 宏名 | 值 | 说明 |
|------|------|-----|------|
| ADC 分辨率 | `BATTERY_ADC_MAX` | 4095 | 12 位 ADC 最大值 |
| 参考电压 | `BATTERY_VREF_MV` | 3300 | 参考电压 3.3V = 3300mV |
| 低电压阈值 | `BATTERY_LOW_MV` | 6000 | 低于此值为低电量 |
| 过压阈值 | `BATTERY_OVER_MV` | 8400 | 高于此值为过压 |

### 1.3 接口定义

#### 1.3.1 adc_to_mv

```c
/**
 * @brief 将 ADC 原始值换算为毫伏电压
 * @param adc_raw ADC 原始值（0 ~ BATTERY_ADC_MAX）
 * @return 换算后的毫伏电压（0 ~ BATTERY_VREF_MV）
 * @note 超过 ADC_MAX 的输入会被钳位到 ADC_MAX
 */
uint16_t adc_to_mv(uint16_t adc_raw);
```

**算法**：
```
if adc_raw > BATTERY_ADC_MAX:
    adc_raw = BATTERY_ADC_MAX
return (uint16_t)((uint32_t)adc_raw * BATTERY_VREF_MV / BATTERY_ADC_MAX)
```

**注意**：使用 `uint32_t` 中间计算避免溢出（4095 * 3300 = 13,513,500，超过 uint16_t 最大值 65,535）。

#### 1.3.2 read_battery_mv

```c
/**
 * @brief 读取电池电压（毫伏）
 * @return 电池电压，单位 mV；ADC 故障时返回 0
 * @note 内部调用 HAL_ADC_GetValue() 获取原始值后换算
 */
uint16_t read_battery_mv(void);
```

**流程**：
1. 调用 `HAL_ADC_GetValue()` 获取 ADC 原始值
2. 调用 `adc_to_mv()` 换算为毫伏
3. 返回结果

### 1.4 依赖

| 依赖 | 类型 | 说明 |
|------|------|------|
| `hal/hal_adc.h` | 头文件 | HAL_ADC_GetValue() 接口声明 |
| `stdint.h` | 标准库 | uint16_t, uint32_t |

## 2. led 模块详细设计

### 2.1 模块概述

LED 指示灯模块，根据电池电压控制红色/绿色 LED 的亮灭，实现低电量/正常/过压三种状态指示。

**文件位置**：
- `app/led/led.h` —— 接口声明 + 状态枚举
- `app/led/led.c` —— 实现

### 2.2 数据结构

#### 2.2.1 LED 状态枚举

```c
typedef enum {
    LED_STATE_OFF = 0,    // 全部熄灭（初始状态）
    LED_STATE_RED,        // 红灯亮（低电量或过压）
    LED_STATE_GREEN       // 绿灯亮（正常）
} led_state_t;
```

#### 2.2.2 GPIO 引脚定义

| 宏名 | 值 | 说明 |
|------|-----|------|
| `GPIO_PIN_LED_RED` | 0 | 红色 LED 引脚号 |
| `GPIO_PIN_LED_GREEN` | 1 | 绿色 LED 引脚号 |
| `GPIO_LEVEL_LOW` | 0 | 低电平（熄灭） |
| `GPIO_LEVEL_HIGH` | 1 | 高电平（点亮） |

### 2.3 接口定义

#### 2.3.1 led_set_by_voltage

```c
/**
 * @brief 根据电池电压设置 LED 状态
 * @param voltage_mv 电池电压，单位 mV
 * @note 状态转换规则：
 *       < 6000mV  → 红灯亮（低电量）
 *       6000~8400 → 绿灯亮（正常）
 *       > 8400mV  → 红灯亮（过压告警）
 */
void led_set_by_voltage(uint16_t voltage_mv);
```

**状态机**：
```
                 ┌─────────────────────────────┐
                 │                             │
                 ▼                             │
           ┌──────────┐   voltage≥6000   ┌─────┴────┐
   初始 ──→│ LED_OFF  │─────────────────→│   GREEN   │
           └────┬─────┘                  └─────┬─────┘
                │                              │
       voltage<6000                   voltage<6000
       或 voltage>8400                 或 voltage>8400
                │                              │
                ▼                              ▼
           ┌──────────┐                 ┌──────────┐
           │   RED    │◄────────────────│   RED    │
           └──────────┘   voltage≥6000  └──────────┘
                            且 ≤8400
```

**实现逻辑**：
```c
void led_set_by_voltage(uint16_t voltage_mv) {
    if (voltage_mv < BATTERY_LOW_MV || voltage_mv > BATTERY_OVER_MV) {
        // 低电量或过压 → 红灯
        HAL_GPIO_SetPin(GPIO_PIN_LED_RED,   GPIO_LEVEL_HIGH);
        HAL_GPIO_SetPin(GPIO_PIN_LED_GREEN, GPIO_LEVEL_LOW);
        current_state = LED_STATE_RED;
    } else {
        // 正常 → 绿灯
        HAL_GPIO_SetPin(GPIO_PIN_LED_RED,   GPIO_LEVEL_LOW);
        HAL_GPIO_SetPin(GPIO_PIN_LED_GREEN, GPIO_LEVEL_HIGH);
        current_state = LED_STATE_GREEN;
    }
}
```

#### 2.3.2 led_get_state

```c
/**
 * @brief 获取当前 LED 状态
 * @return 当前状态（LED_STATE_OFF/RED/GREEN）
 */
led_state_t led_get_state(void);
```

### 2.4 内部状态

```c
static led_state_t current_state = LED_STATE_OFF;
```

模块内部维护当前状态，初始为 `LED_STATE_OFF`。每次调用 `led_set_by_voltage()` 更新。

### 2.5 依赖

| 依赖 | 类型 | 说明 |
|------|------|------|
| `hal/hal_gpio.h` | 头文件 | HAL_GPIO_SetPin() 接口声明 |
| `app/battery/battery.h` | 头文件 | 电压阈值宏（BATTERY_LOW_MV / BATTERY_OVER_MV） |
| `stdint.h` | 标准库 | uint16_t |

## 3. HAL 接口详细设计

#ifndef HAL_ADC_H

/**

## 4. 固件主程序详细设计

### 4.1 文件位置

`platform/firmware/firmware_main.c`

### 4.2 真实 HAL 模拟实现

为了在 PC 上模拟固件运行，提供了 HAL 接口的模拟实现：

```c
// ADC 模拟：返回 0~4095 的随机值
uint16_t HAL_ADC_GetValue(void) {
    return (uint16_t)(rand() % 4096);
}

// GPIO 模拟：打印设置信息
void HAL_GPIO_SetPin(uint8_t pin, uint8_t level) {
    printf("[HAL] GPIO pin=%d set to %d\n", pin, level);
}
```

### 4.3 主循环

```c
int main(void) {
    srand((unsigned)time(NULL));
    printf("=== Firmware Demo ===\n");
    for (int i = 0; i < 5; i++) {
        uint16_t mv = read_battery_mv();
        led_set_by_voltage(mv);
        printf("[%d] Battery: %u mV, LED: %s\n",
               i, mv,
               led_get_state() == LED_STATE_RED ? "RED" :
               led_get_state() == LED_STATE_GREEN ? "GREEN" : "OFF");
        sleep(1);
    }
    return 0;
}
```

**注意**：`sleep(1)` 在 Windows 上需要 `#include <windows.h>`，在 Linux/macOS 上需要 `#include <unistd.h>`。使用条件编译处理跨平台差异。

## 5. 测试固件（test_support.c）详细设计

### 5.1 作用

统一管理所有测试用例的 setUp/tearDown 和 main 函数，避免每个测试文件重复编写。

### 5.2 setUp

```c
void setUp(void) {
    mock_hal_adc_Init();   // 初始化 ADC 桩（清空期望队列）
    mock_hal_gpio_Init();  // 初始化 GPIO 桩
}
```

每个测试用例执行前自动调用，确保桩状态干净。

### 5.3 tearDown

```c
void tearDown(void) {
    mock_hal_adc_Verify();   // 校验 ADC 调用次数与期望一致
    mock_hal_adc_Destroy();  // 销毁 ADC 桩（释放内存）
    mock_hal_gpio_Verify();  // 校验 GPIO 调用次数
    mock_hal_gpio_Destroy(); // 销毁 GPIO 桩
}
```

每个测试用例执行后自动调用，`Verify()` 会检查实际调用次数是否与 `Expect()` 设置的一致，不一致则测试失败。

### 5.4 main

```c
int main(void) {
    UNITY_BEGIN();
    // battery 模块测试（11 个）
    RUN_TEST(test_adc_to_mv_normal);
    RUN_TEST(test_adc_to_mv_below_max);
    // ... 共 19 个 RUN_TEST
    return UNITY_END();
}
```

新增模块时，在此添加测试函数的 `extern` 声明和 `RUN_TEST()` 调用。

## 6. CMock 桩生成配置

### 6.1 gen_mocks.rb

```ruby
require 'cmock'
config = YAML.load_file('tools/CMockConfig.yml')
cmock = CMock.new(config)

# 要生成桩的头文件列表
header_files = [
  'hal/hal_adc.h',
  'hal/hal_gpio.h'
]
cmock.setup_mocks(header_files)
```

新增 HAL 接口时，在此数组中添加头文件路径，重新运行 `ruby tools/gen_mocks.rb`。

### 6.2 CMockConfig.yml

```yaml
:cmock:
  :mock_prefix: mock_          # 桩文件名前缀（mock_hal_adc.h）
  :mock_path: test/mocks       # 桩输出目录
  :plugins:
    - :expect                  # 支持 Expect() 预设返回值
    - :ignore                  # 支持 Ignore() 忽略调用
  :treat_as:
    uint8: HEX8
    uint16: HEX16
    uint32: HEX32
```

## 7. 关键设计决策

| 决策 | 理由 |
|------|------|
| adc_to_mv 用 uint32_t 中间计算 | 4095*3300 超过 uint16_t，必须提升位宽避免溢出 |
| led 模块维护内部状态 | 避免每次查询都重新计算，状态机模式更清晰 |
| HAL 只有 .h 没有 .c | 实现由平台层和测试桩分别提供，实现多态 |
| test_support.c 统一管理 setUp | 新增模块只需改一个文件，避免多处维护 |
| 桩文件检入仓库 | 无 Ruby 环境也能编译，降低使用门槛 |
